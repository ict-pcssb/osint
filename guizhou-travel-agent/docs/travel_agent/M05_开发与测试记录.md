## 1 实现与范围

- 增加按 ID 解析的 POI、入口、站点和线路方向目录。复用 M4 核对过的浮玉桥两端入口和参考项目的铜仁站坐标。线路方向与官网入口均为独立字段。缺精确点位时保持缺失，同名返回候选。核对线路拓扑使用[贵阳市政府地铁 1 号线资料](https://english.guiyang.gov.cn/2026-07/01/c_1056570.htm)。公开资料查找只用于标注目录来源，没有计入项目的真实核验链。
- 证据服务复用 `travel_search_mcp.search_travel_sources`，默认仍为 Exa 后 AnySearch。摘要、已读原文和 Claim 记录独立。Parallel 仅在显式选择时通过独立的搜索和原文回读入口，首次固定测试使用替身，收尾实测仅启用了显式、独立的 Parallel 原文回读。公开网页读取仅在显式启用时工作，限制 HTTPS 主机，校验 DNS 地址，并连接到同一个已校验的公开 IP。限制正文大小，重查跳转目标。登录页、私网地址、认证型查询参数和非文本正文均不作为可用证据。
- 核验逐项比较实体、入口、方向和适用日期，区分发布日和生效期。记录检索候选、原文短摘录、哈希、采集和过期时间，按原链接、canonical URL 或正文哈希归并来源。相反结论仍保留。仅正式适用的原文能确认事实，模拟原文抽取成功也不会被标成真实确认。
- 接入现有单 Agent 的核验输出和 M2 核验卡。已保存时间轴按会话身份读取后，可用准确的站点入口和行程日发起独立核验，既有版本不改写。直接核验的材料和缓存留在内存及响应内，业务写入为零。M4 按显式保存持久化原有时间轴证据的行为保持。旧的只有 ID 或 URL 的记录可以通过兼容转换标为 `legacy_unverified`，采集时间及适用日缺项保持 null。
- 只读检查了旧 `travel_plan.retrieve`、`travel_weekend.confirmed_excerpt` 和本地 mock KB 的 `/v1/retrieve` 契约。新增适配器以该协议读取脱敏检索响应；没有用旧 AnySearch 直连替代现有 MCP 链，未启用正式 KB、Parallel 搜索或 `notice.lookup` 服务，也未安装依赖。
