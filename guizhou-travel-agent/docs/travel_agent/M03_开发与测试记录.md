## 1 验收范围与环境

以 M03 全文、00A 的共用测试要求、00B 的状态与 E1 契约、00C 的单项澄清与 00D 的隔离、幂等及观测条款为依据。M2 已由用户确认通过。M1 转入本模块的两个账号、跨账号读写拒绝、回滚和复跑无残留均实际验证。

桌面新项目原本没有账号、数据库或 Web 聊天入口。我将 Python 内置的 **SQLite 3.51.0 磁盘文件选为新项目首个本地后端**，保留现有 Python 3.13.11 和 qwen4-max。没有替换一个已经在用的数据库。只读核对了旧项目 Profile 的 `intended_region` 和旧草稿预览。旧项目 MySQL 无法作为本次验收环境，未指定其测试 DSN，本机 Docker 引擎也未就绪。

每项数据库测试都使用独立临时目录中的全新 SQLite 文件。两名测试用户通过本项目真实账号创建和密码登录获得会话，应用用登录身份检查数据归属。DBGuard 只允许打开当次隔离文件。数据、账号和密码均为本地测试专用，测试结束实际删除临时目录。没有连接旧项目库或生产库，没有新增或升级依赖。

## 3 实现和文件路径

| 路径 | 用途 |
| --- | --- |
| `travel_state.py` | SessionContext、TripDraft、TripVersion、PreferenceConsent、字段来源、日期、预算及锁定 |
| `travel_state_app.py`、`contracts/travel_agent/v1/state.sql` | 真实本地账号与会话、偏好许可、归属查询、独立保存事务及 SQLite 持久状态结构 |
| `travel_state_cli.py`、`travel_agent.py` | 可选的本地账号与状态入口，明确预览、保存、读取 |
| `travel_routing.py`、`contracts/travel_agent/v1/intent.schema.json` | 在原 `Conversation.ask` 中接上上下文、指代和锁定追问 |
| `tests/travel_agent/m03/test_m03.py`、`tests/travel_agent/support/guards.py` | M3 验收断言、独立文件库守卫与清理 |
| `scripts/travel_agent/run_module.py`、`docs/travel_agent/evidence/m03/` | M03 分层结果、脱敏追踪及回归证据 |

本地 CLI 用 `--state-db <本地.sqlite3>` 显式启用。加 `--create-account` 可在同一文件创建本地账号。启动后通过 `preview` 在内存整理行程字段，再以 `save: true` 和幂等键明确保存，或读取自己保存的行程。真实网页、正式导出文件、完整可编辑路线时间轴不在此入口实现。退出时删除本次 CLI 登录会话。
