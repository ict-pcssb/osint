## 实际执行命令

在桌面 `guizhou-travel-agent` 项目根目录用 PowerShell 执行。以下为通过的复测命令，均返回 0。

```powershell
$env:PYTHONPATH = (Resolve-Path 'tests/travel_agent').Path
.\.venv-flight\Scripts\python.exe -B -m unittest discover -s tests/travel_agent/m06 -v

.\.venv-flight\Scripts\python.exe -B scripts/travel_agent/run_module.py M06 --report docs/travel_agent/evidence/m06/fixed/report.json
foreach ($module in 'M01','M02','M03','M04','M05') {
  .\.venv-flight\Scripts\python.exe -B scripts/travel_agent/run_module.py $module --report "docs/travel_agent/evidence/m06/$module-regression/report.json"
}
.\.venv-flight\Scripts\python.exe -B scripts/travel_agent/run_module.py M01 --suite new-regression --report docs/travel_agent/evidence/m06/search-regression/report.json
.\.venv-flight\Scripts\python.exe -B scripts/travel_agent/demo_m04.py --browser 'C:/Program Files/Google/Chrome/Application/chrome.exe' --output docs/travel_agent/evidence/m06/browser
.\.venv-flight\Scripts\python.exe -B scripts/travel_agent/preview_m02.py --browser 'C:/Program Files/Google/Chrome/Application/chrome.exe' --output docs/travel_agent/evidence/m06/m02-browser/preview.html
.\.venv-flight\Scripts\python.exe -I -B -m pip check
```

先写十项断言及夹具，再实现规则和接入。第一次 M06 运行因规则模块尚不存在而 FAIL。规则初版跑通九项，修正集成测试漏传的固定时钟后通过。M04 和 M05 首次直接运行 `unittest discover` 因未载入 `tests/travel_agent` 的 `support` 而 FAIL，之后用仓库已有 runner 重跑通过。Chrome 首次执行时，网页契约检查未支持规则报告新增的动态字段，渲染 FAIL，修正并复跑通过。补测时间轴 API 错站加缺价时，先发现旧入口采纳了错站路段，补上返回 ID 检查后通过。最终 M06 报告为 10 PASS、0 FAIL、0 BLOCKED、0 SKIPPED。这四个数仅统计固定套件，未安排的实测单列在上表。

## 保留范围与回滚

现有贵阳两天试用页沿用全团预算，费用范围为住宿、餐饮、市内交通和门票，锁定的返程票单列。M6 计算层同时验证了人均口径。首版真实政策文件、景区实际收费和站内预留仍需按地点核实，演示中的费用和进站预留是模拟或配置估算。正式门票归档时需给出适用日期及对应原文。本轮无需供应商权限或凭据即可验收 M6。

如需暂停新时间轴提交，将服务进程的 `TRAVEL_RULES_POLICY_VERSION` 设为 `disabled` 并重启本地入口。保存入口会拒绝新写入，历史仍可读取。本轮已用隔离数据库验证暂停后拒绝提交及恢复后的正常保存。若需要回退代码，先维持暂停提交，再从 M5 的已验收源码备份恢复本轮改动，复跑家庭费用、锁定项和跨午夜三组规则检查，启用通过验收的版本后再恢复提交。旧行程报告随其版本保留。
